**Geko** does speech in both directions, on **one API key** and **one balance**:

- **[Text-to-speech](/tts)** — send a string and a voice name, get audio back. Speaks **Kazakh** today (`tokay-kk-v1`) in six named voices.
- **[Speech-to-text](/stt)** — send audio, get text back. Recognises **Kazakh and Russian** (`seta-kk-ru-v2`), including a speaker switching language **mid-sentence**, at **8.71% WER** where Whisper large-v3 scores 44.95% on the same audio.

More languages arrive on the same endpoints, so the code you write now keeps working.

It's designed to feel familiar (OpenAI / ElevenLabs style): a **thin, typed SDK**, a **CLI**, and a **simple HTTP API**. Pick whichever fits.

## try it in one line

No signup code required — grab a key and run:

```bash
export GEKO_API_KEY=sk-tokay-...

npx @gekoai/sdk say "Сәлеметсіз бе!" --voice Aigerim -o hello.wav   # text → speech
npx @gekoai/sdk transcribe hello.wav                                # speech → text
```

## the API in a nutshell

Synthesis takes text + a voice and returns **WAV (24 kHz, 16-bit PCM, mono)**. Transcription takes audio and returns JSON with the text. The surface is small:

| Method | Endpoint | Auth | What it does |
| --- | --- | --- | --- |
| `POST` | `/v1/tts` | required | synthesize text → `audio/wav` |
| `POST` | `/v1/tts/stream` | required | streaming synthesis (chunked) |
| `POST` | `/v1/audio/speech` | required | OpenAI-compatible synthesis alias |
| `POST` | `/v1/transcribe` | required | transcribe audio → text |
| `POST` | `/v1/audio/transcriptions` | required | OpenAI-compatible transcription alias |
| `GET` | `/v1/models`, `/v1/voices`, `/health` | open | catalog + status |

**Base URLs.** Text-to-speech: `https://geko--tokay-serve-web.modal.run`. Speech-to-text: `https://geko--seta-serve-transcriber-api.modal.run`. Two separately scaled GPU services — the [SDK](/sdk/typescript) hides the split, so one client and one key reach both.
